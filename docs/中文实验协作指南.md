# StreamVGGT 中文实验协作指南

本文档对应 GitHub 仓库 [yyyds1/StreamVGGT](https://github.com/yyyds1/StreamVGGT)，使用分支 `head-camera-temporal`。除下载命令中的仓库地址外，所有路径均通过仓库相对路径或环境变量表达，不绑定特定机器目录。命令默认从 `StreamVGGT` 根目录执行。

## 一、环境配置

### 1. 获取代码

```bash
git clone --branch head-camera-temporal --single-branch https://github.com/yyyds1/StreamVGGT.git
cd StreamVGGT
git switch head-camera-temporal
git branch --show-current
```

已有 checkout 时，确认输出为 `head-camera-temporal`，并确认远端为 `https://github.com/yyyds1/StreamVGGT.git`。

### 2. 创建 Conda 环境

```bash
conda create -n ActionVGGT python=3.11 cmake=3.14.0 -y
conda activate ActionVGGT
python -m pip install --upgrade pip
pip install -r requirements.txt
conda install -y 'llvm-openmp<16'
```

训练需使用与 NVIDIA 驱动兼容的 PyTorch/CUDA。RoboTwin 仿真测试还需按 [RoboTwin 官方安装文档](https://robotwin-platform.github.io/doc/usage/robotwin-install.html)准备 Vulkan、SAPIEN 和仿真资产。

```bash
nvidia-smi
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

### 3. 约定目录和环境变量

建议两个 checkout 并列放置：

```text
workdir/
├── StreamVGGT/
│   ├── ckpt/
│   │   └── ActionVGGT/
│   ├── dataset/
│   │   ├── robotwin-labeled-awe-train/
│   │   └── robotwin-labeled-awe-eval/
│   ├── src/
│   └── train_out/
└── robotwin-labeled/
```

在 `StreamVGGT` 根目录设置变量：

```bash
export STREAMVGGT_ROOT="$PWD"
export TRAIN_DATASET="$STREAMVGGT_ROOT/dataset/robotwin-labeled-awe-train"
export EVAL_DATASET="$STREAMVGGT_ROOT/dataset/robotwin-labeled-awe-eval"
export ROBOTWIN_ROOT="$(cd ../robotwin-labeled && pwd)"
export TRAIN_OUT="$STREAMVGGT_ROOT/train_out"
```

如果两个仓库不在同一父目录，只修改 `ROBOTWIN_ROOT`，不要修改文档中的仓库相对结构。

## 二、数据集下载

当前使用 ModelScope 数据集仓库：

- 训练集：[`yyyyds139/robotwin-labeled-awe-train`](https://modelscope.cn/datasets/yyyyds139/robotwin-labeled-awe-train)
- 测试集：[`yyyyds139/robotwin-labeled-awe-eval`](https://modelscope.cn/datasets/yyyyds139/robotwin-labeled-awe-eval)

安装 ModelScope 并下载：

```bash
pip install modelscope
mkdir -p dataset
modelscope download --dataset yyyyds139/robotwin-labeled-awe-train \
  --local_dir "$TRAIN_DATASET"
modelscope download --dataset yyyyds139/robotwin-labeled-awe-eval \
  --local_dir "$EVAL_DATASET"
```

下载后检查：

```bash
find "$TRAIN_DATASET" -maxdepth 2 -type f | head
find "$EVAL_DATASET" -maxdepth 2 -type f | head
```

训练命令的 `--dataset-path` 必须指向实际包含数据集元数据和 episode 文件的目录。如果 ModelScope 下载后多了一层同名目录，将 `TRAIN_DATASET` 或 `EVAL_DATASET` 调整到实际数据根目录；不要改动数据文件名和内部结构。

## 三、checkpoint 下载

当前模型仓库为 ModelScope [`yyyyds139/ActionVGGT`](https://modelscope.cn/models/yyyyds139/ActionVGGT)。下载到项目内的 `ckpt/ActionVGGT`：

```bash
mkdir -p ckpt
modelscope download --model yyyyds139/ActionVGGT \
  --local_dir "$STREAMVGGT_ROOT/ckpt/ActionVGGT"
find ckpt/ActionVGGT -maxdepth 4 -type f
```

原始 StreamVGGT、DINOv2 和实验 ActionVGGT checkpoint 均统一从 `yyyyds139/ActionVGGT` 下载，不再使用 Hugging Face、清华云或其他旧来源：

```bash
modelscope download --model yyyyds139/ActionVGGT \
  --include 'original/**' --local_dir "$STREAMVGGT_ROOT/ckpt/ActionVGGT"
modelscope download --model yyyyds139/ActionVGGT \
  --include 'experiments/checkpoint_step_28000/**' \
  --local_dir "$STREAMVGGT_ROOT/experiments/checkpoint_step_28000"
```

推理时使用 `$STREAMVGGT_ROOT/experiments/checkpoint_step_28000`；训练初始化所需的原始 StreamVGGT 和 DINOv2 文件位于 `$STREAMVGGT_ROOT/ckpt/ActionVGGT/original/`。不要把下载机器的 home、容器挂载点或其他绝对路径写入配置和文档。

注意：当前仓库部分历史配置文件可能仍含旧机器路径。训练时用命令行 `--dataset-path "$TRAIN_DATASET"` 覆盖数据路径；若配置中的模型权重路径与本地目录不一致，应在派生配置中改为仓库相对路径后再运行。

## 四、训练入口

训练主程序是 `src/train_va.py`，推荐使用 `src/scripts/run_va_train.sh`。脚本默认值为 `CONFIG_NAME=vga_robotwin_train`、`NGPU=8`、`SAVE_ROOT=./train_out`，并默认只训练 `adjust_bottle`；设置 `SINGLE_TASK=` 为空表示按配置训练全部任务。

### 训练必填参数表

| 参数 | 必填性 | 说明 |
|---|---|---|
| `--config-name` / `CONFIG_NAME` | 必填 | 配置名；默认 `vga_robotwin_train`，对应 `src/configs/va_vga_robotwin_train_cfg.py` |
| `--dataset-path` | 必填 | 训练数据根目录；应使用 `TRAIN_DATASET` 覆盖配置中的旧路径 |
| `--save-root` / `SAVE_ROOT` | 建议显式设置 | checkpoint 和日志输出根目录 |
| `NGPU` | 按机器设置 | 单机训练使用的 GPU 数，必须不超过可用 GPU 数 |
| `SINGLE_TASK` | 可选 | 单任务名；置空则不传 `--single-task` |

### 8 卡全任务训练

```bash
cd "$STREAMVGGT_ROOT"
NGPU=8 \
CONFIG_NAME=vga_robotwin_train \
SAVE_ROOT="$TRAIN_OUT/vga_robotwin_train" \
SINGLE_TASK= \
bash src/scripts/run_va_train.sh \
  --dataset-path "$TRAIN_DATASET"
```

### 单卡单任务调试

```bash
NGPU=1 \
SAVE_ROOT="$TRAIN_OUT/debug_adjust_bottle" \
SINGLE_TASK=adjust_bottle \
bash src/scripts/run_va_train.sh \
  --dataset-path "$TRAIN_DATASET"
```

继续训练时显式指定完整 checkpoint 目录：

```bash
NGPU=8 \
SAVE_ROOT="$TRAIN_OUT/vga_robotwin_train" \
bash src/scripts/run_va_train.sh \
  --dataset-path "$TRAIN_DATASET" \
  --resume-checkpoint-dir "$TRAIN_OUT/vga_robotwin_train/checkpoint_step_2000"
```

训练产物位于 `SAVE_ROOT` 下。一个可用于测试的完整 `checkpoint_step_*` 目录应至少包含 `training_config.json`、`transformer/` 和 `action_head/`。训练日志直接查看终端；若配置使用 TensorBoard，可运行：

```bash
tensorboard --logdir "$TRAIN_OUT/vga_robotwin_train" --bind_all
```

## 五、测试入口

测试由模型服务端和 RoboTwin 客户端组成：服务端加载 checkpoint 并监听端口，客户端启动仿真、发送任务并写出成功率。两者需要在网络互通且能够访问 RoboTwin 资产的环境中运行。默认服务端端口为 `29055`。

### 测试必填参数表

| 参数 | 必填性 | 说明 |
|---|---|---|
| `CKPT_DIR` | 必填 | 完整 `checkpoint_step_*` 目录，必须含 `training_config.json`；未设置时服务端会在 `TRAIN_OUT_ROOT` 中寻找最新完整 checkpoint |
| `EVAL_CONFIG` | 通常自动 | 默认使用 `$CKPT_DIR/training_config.json`，只有需要覆盖时才显式设置 |
| `PORT` | 服务端和客户端一致 | 服务监听端口，默认 `29055` |
| `SAVE_ROOT` | 建议显式设置 | 测试结果、视频和汇总表目录 |
| `TASK_NAME` 或 `TASKS` | 可选 | 单任务或任务集合；均未设置时运行客户端内置任务列表 |
| `TEST_NUM` | 建议显式设置 | 每个任务的测试 demo 数，默认 10 |
| `TASK_CONFIG` | 按测试数据设置 | RoboTwin 任务配置，脚本默认 `demo_clean` |
| `MAX_EPISODE_STEPS` | 按实验协议设置 | 单回合最大仿真步数；不设置时使用任务配置默认值 |

### 启动服务端

另开终端执行：

```bash
cd "$STREAMVGGT_ROOT"
CKPT_DIR="$TRAIN_OUT/vga_robotwin_train/checkpoint_step_2000" \
TRAIN_OUT_ROOT="$TRAIN_OUT" \
START_PORT=29055 \
bash src/scripts/launch_server.sh
```

### 启动客户端

```bash
cd "$STREAMVGGT_ROOT"
CKPT_DIR="$TRAIN_OUT/vga_robotwin_train/checkpoint_step_2000" \
SAVE_ROOT="$STREAMVGGT_ROOT/evaluation_runs/vga_robotwin_train/checkpoint_step_2000" \
TASK_CONFIG=demo_clean \
TEST_NUM=10 \
PORT=29055 \
MAX_EPISODE_STEPS=400 \
bash src/scripts/launch_client.sh
```

单任务示例：

```bash
TASK_NAME=adjust_bottle \
CKPT_DIR="$TRAIN_OUT/vga_robotwin_train/checkpoint_step_2000" \
SAVE_ROOT="$STREAMVGGT_ROOT/evaluation_runs/adjust_bottle" \
TEST_NUM=10 PORT=29055 \
bash src/scripts/launch_client.sh
```

如使用评测集里的缓存 sparse waypoint，必须同时设置缓存根目录和 seed 根目录：

```bash
USE_CACHED_SPARSE_WAYPOINTS=1 \
SPARSE_WAYPOINT_DATASET_ROOT="$EVAL_DATASET" \
EVALUATION_SEED_ROOT="$EVAL_DATASET" \
CKPT_DIR="$TRAIN_OUT/vga_robotwin_train/checkpoint_step_2000" \
SAVE_ROOT="$STREAMVGGT_ROOT/evaluation_runs/cached_waypoint" \
TEST_NUM=10 PORT=29055 \
bash src/scripts/launch_client.sh
```

### 查看结果

- 客户端结束时会打印 `summary_file` 和已完成任务的平均成功率。
- 汇总表为 `SAVE_ROOT/success_rates_*.tsv`，包含任务名、成功率、成功数、总数、状态和指标文件路径。
- 单任务指标通常位于 `SAVE_ROOT/stseed-*/metrics/<task>/res.json`；重点检查 `succ_rate`、`succ_num` 和 `total_num`。
- 视频、失败日志和其他原始输出均保留在 `SAVE_ROOT` 下。实验记录应同时保存命令、环境变量、checkpoint、任务列表和 seed 清单。

### Absolute-EE waypoint-noise ablation

本组实验专门评估已训练的 noisy gripper-midpoint waypoint + absolute EE action space + wrist DINOv2 + VGGT LoRA checkpoint 对 waypoint 测试条件变化的敏感性。所有条件必须使用同一个 checkpoint、同一任务顺序、同一份 50-task evaluation seed 列表、每任务 10 个 episode、相同 `TASK_CONFIG`、`MAX_EPISODE_STEPS`、headless 设置及推理参数；除 profile 指定的 waypoint noise / 缺失 / camera 条件外，不改变其他设置。推荐先运行 EE-N0、EE-N1、EE-N2、EE-N3；EE-M1、EE-M3、EE-C1 是额外鲁棒性压力测试，缺失条件不是只改变噪声幅度的直接对照。不要把跨 checkpoint 或跨 seed 的历史总成功率作噪声因果结论。

- 推荐 checkpoint：ModelScope [`yyyyds139/ActionVGGT`](https://modelscope.cn/models/yyyyds139/ActionVGGT) 下的 `experiments/midpoint_ee_wrist_dinov2_noisy_lora_50tasks_8xh100_20261104_r2/checkpoint_step_32000/`。
- checkpoint 目录应包含 `training_config.json`、`transformer/`（VGGT adapter 和 LoRA 权重）及 `action_head/`；推理使用 checkpoint 内配置，不需要训练状态文件 `training_state.pt`。
- 当前模型加入了 wrist DINOv2 条件输入，协作者需在模型仓库下载 `original/**` 和 `dinov2-small/**` 到 `ckpt/ActionVGGT/`，并确保 `ckpt/dinov2-small` 权重完整可读（训练配置现在按仓库根目录解析该相对位置）。不要在代码配置中保留训练机绝对路径。
- ModelScope Access Key 不写入脚本、文档、shell history 或 Git。需要上传时使用环境变量/交互式登录，并确保 token 不进入进程日志。

下载新增 checkpoint：

```bash
modelscope download --model yyyyds139/ActionVGGT \
  --include 'experiments/midpoint_ee_wrist_dinov2_noisy_lora_50tasks_8xh100_20261104_r2/checkpoint_step_32000/**' \
  --local_dir "$STREAMVGGT_ROOT/experiments/midpoint_ee_wrist_dinov2_noisy_lora_50tasks_8xh100_20261104_r2"
export CKPT_DIR="$STREAMVGGT_ROOT/experiments/midpoint_ee_wrist_dinov2_noisy_lora_50tasks_8xh100_20261104_r2/checkpoint_step_32000"
```

如果 ModelScope 返回目录层级不同，按实际下载结果设置 `CKPT_DIR`，并检查 `training_config.json`、`transformer/` 和 `action_head/` 均存在。下载模型组件：

```bash
modelscope download --model yyyyds139/ActionVGGT \
  --include 'original/**' --local_dir "$STREAMVGGT_ROOT/ckpt/ActionVGGT"
modelscope download --model yyyyds139/ActionVGGT \
  --include 'dinov2-small/**' --local_dir "$STREAMVGGT_ROOT/ckpt/ActionVGGT"
```

推荐通过仓库脚本逐条件运行。以下命令例示 EE-N0；更换 profile 启动脚本即可运行其他条件。`EVAL_DATASET` 必须是包含固定 `evaluation_seeds.txt` 的测试集根目录，确保所有条件复用同一批 seed。单机多卡评测建议每个 worker 设置独立 `PORT`、`EVAL_GPU`、`TASKS` 子集和 `SAVE_ROOT`，最后合并 TSV 并按 episode 数加权统计，不可平均各分片百分比。

```bash
cd "$STREAMVGGT_ROOT"
export CKPT_DIR="$STREAMVGGT_ROOT/experiments/midpoint_ee_wrist_dinov2_noisy_lora_50tasks_8xh100_20261104_r2/checkpoint_step_32000"
export SAVE_ROOT="$STREAMVGGT_ROOT/evaluation_runs/ee_midpoint_waypoint_ablation"
export TEST_NUM=10 TASK_CONFIG=demo_clean MAX_EPISODE_STEPS=400 PORT=29055
export USE_CACHED_SPARSE_WAYPOINTS=1
export SPARSE_WAYPOINT_DATASET_ROOT="$EVAL_DATASET"
export EVALUATION_SEED_ROOT="$EVAL_DATASET"
export STRICT_SCENE_REPLAY=1
bash src/scripts/ablation/run_EE-N0_clean_waypoint.sh
```

所有 profile 的 waypoint 噪声由评测端对观测条件即时注入，checkpoint 内的训练噪声设置不会覆盖 profile；这组实验因此是固定 noisy-trained 模型的**推理条件鲁棒性测试**，不是训练噪声因果消融。
